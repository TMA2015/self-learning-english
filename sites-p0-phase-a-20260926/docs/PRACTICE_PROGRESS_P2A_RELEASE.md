# v21-P2A Learning Evidence and Practice Progress — stage only

Source parent: actual deployed Sites v25 `a7a05cc937c4fc43dce61f993d19d167c068d877`. PR #19 supplies the evidence audit, not application code or Batch05 content. This implementation changes no importer, package, schema, authentication or answer key.

`GET /api/practice-progress` is authenticated and pure. It reads account-scoped saved `academic_attempts`, `writing_submissions` and `writing_evaluations`, and the imported package metadata. No legacy `/api/state` GET, rebuild, snapshot, evidence write or backfill runs. Saved `results[].correct` is used as originally graded; exact package ID, content version and question ID form coverage identity. A missing historical package does not cause its saved answer to be regraded or dropped. Only submitted objective results enter answer accuracy. `started`, `unassessed`, and null-correct Writing responses are excluded from its denominator.

Overall: correct saved objective answer events / all saved objective answer events across attempts. A multi-tag question is one answer event overall and one correlated observation for each tag. Distinct coverage counts immutable package/version/question identities. Skill and tag tables disclose their own numerator, denominator and distinct-question count. Repeated mistake means the same exact-version question has at least two incorrect submitted attempts. Missing evidence is `—`/not observed, never 0% mastery. Recommendations need at least two saved observations and below 70% correct; they name an available matching lesson when one exists, and lead to manual skill Catalog selection. Recommendations and practice accuracy cannot certify CEFR or change diagnostic/working-level logic.

Foundation Writing shows pending versus adult-approved attempts separately. Legacy Writing Coach submissions show approved only when their saved evaluation status is `approved`; drafts, pending, failed, automatic and awaiting-approval evaluations are not approved quality scores. All original reviews, revisions, audio, attempts and learning-evidence rows are untouched.

Local tests include correlated tags, repeats, versioned identity, missing observations, Writing review status, read-only route and account-scope repository bindings. Browser QA on an authenticated staging identity remains owner pending if unavailable. Owner should compare Dashboard and Progress on desktop/mobile, open an old submitted result and a repeated attempt, confirm denominators, pending/approved Writing labels and manual Catalog access. Check zero-data state with an authorized test account. This is not a production release.
