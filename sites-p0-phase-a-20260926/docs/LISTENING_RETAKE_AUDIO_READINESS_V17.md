# Listening Retake — independent answer and audio readiness

**Owner QA finding on live v16.1 (Sites release number 17):** In an authenticated iPhone session, the missing-answer warning, focus, completion counter, successful first submission, scoring and previously saved attempts all worked. On a further attempt the player displayed “All questions answered. Submit when you are ready” but Submit was disabled. One screenshot also shows A2 Listening submitted while B1 Listening is a saved draft; screenshot alone cannot prove which attempt was retaken or whether that particular attempt had verified full playback.

**Source cause:** The answer counter only checked whether all answer fields were nonblank. The Submit button separately had `lesson.module==='listening'&&!attempt.playbackCompleted` in its disabled condition, so “ready” and actual eligibility contradicted each other without actionable error next to Submit. The backend correctly requires full audio playback proof **for each individual attempt**; answer completion cannot substitute for playback. In addition, the old Retake function did not explicitly reset local audio counters/token or invalidate delayed asynchronous playback events.

**Fix (source-only):**
- Show two distinct statuses in the answer-action area: N/N answered, and verified/unverified audio **for this attempt**. Never claim submission is ready based solely on answers.
- Allow Submit when the player is otherwise idle; if answers are missing, retain the existing in-player actionable warning and focus first missing answer. If full playback is unverified, display an action-area warning and scroll to the audio controls instead of silently disabling Submit. Do not call server scoring for either incomplete condition.
- Retake creates a fresh server attempt with blank answers, explicitly resets pause/counters/token and invalidates delayed playback work. Starting/restarting audio clears any previous local confirmation; only a successful server-verified playback response updates the corresponding attempt to `playbackCompleted=true`.
- Playback interruptions or server-verification errors are shown at the audio panel and action area, not only above the player. Keep the real-playback time guard and authoritative server submit validation unchanged.
- If audio is unavailable, use the existing explicit unassessed skip pathway, never fabricate a Listening score.
